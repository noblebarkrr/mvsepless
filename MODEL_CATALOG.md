## Схема каталога моделей

```json
{
    "model_name": { # короткое имя модели для инференса
        # Информация о модели
        "model_type": "mel_band_roformer", # тип модели
        "category": "Вокал", # категория
        "id": 1, # ID (для кастомного каталога используется любое отрицательное число)
        "full_name": "Full Name of Model Name", # полное имя модели
        "stems": [ # список стемов

            "stem1",
            "stem2"
        ],
        "target_instrument": "stem1", # целевой инстурмент (null если нет целевого инструмента)
        "checkpoint_url": "https://example.com/model.ckpt", # ссылка на файл модели (чекпоинт)
        "checkpoint_parts": [ # суффиксы частей чекпоинта, если он разделён на несколько частей
            "_part1", ... и т.д.
        ],
        "config_url": "https://example.com/config.yaml" # ссылка на конфигурационный файл с параметрами модели
    }, ... и т.д.
}
```

## Правила при работе с каталогом моделей
- `Кастомный` каталог - это дополнение к `стандартному` каталогу моделей, а не его замена
- Ссылка должна отдавать сам файл, а не информацию о нём `(*.pth, *.ckpt, *.onnx, *.yaml)`
- Если файл модели находится на `Google Диске` или любом на другом облачном хранилище, то файл нужно перезалить в свой публичный репозиторий (не `Gated`, а  `Public`) на `Hugging Face` или в релизы одного из своих публичных репозиториев на `Github` (лимит - 2 гб)
- Порядок стемов необязателен, но список стемов и целевой инструмент должны совпадать с теми, что есть в конфиге модели
- Если в конфиге целевой инструмент обозначен как `null`, то в информации о модели указываем его как `null` без кавычек
- Для `стандартного` каталога в качестве ID модели используются положительные числа, а для `кастомного` - отрицательные
- Каждое имя и ID модели не могут повторяться дважды во всём каталоге моделей

### Примеры, где могут находится стемы и целевой инструмент в конфиге модели:
```yaml
training:
    instruments:
        - stem1
        - stem2
    target_instrument: stem1
```
```yaml
training:
    instruments:
        - stem1
        - stem2
    target_instrument: null
```
```yaml
training:
    instruments: ["stem1", "stem2"]
    target_instrument: stem1
```
```yaml
training:
    instruments: ["stem1", "stem2"]
    target_instrument: null
```
